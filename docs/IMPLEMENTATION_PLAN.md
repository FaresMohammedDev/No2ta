# دراسة التطوير وخطة التنفيذ — 4 نوفمبر 2026

## الهدف وحدود الدفعة

تحويل قائمة المقترحات إلى مراحل قابلة للاختبار، مع الحفاظ على Express وSQLite وواجهة JavaScript الحالية. بدء التنفيذ لا يعني اعتبار جميع المقترحات منجزة. الدفعة الحالية تعالج سجل الرسائل؛ التغييرات السابقة للأصول المحلية والاستريكات تبقى ضمن مساحة العمل ولم تُرفع بعد.

## تقييم الوضع

- الواجهة والأيقونات والخطوط أصبحت محلية، لكن المعاينة البصرية لم تُنجز بسبب رفض المتصفح المحلي سابقًا.
- GET /api/messages كان يرجع أقدم 150 رسالة. لا توجد آلية تحميل تاريخ المحادثة.
- لا توجد جلسة مصادقة تربط كل HTTP request وSocket بالمستخدم. لا يكفي تعديل تسجيل الدخول منفردًا: يجب مراجعة الرسائل والجروبات والمرفقات وأوامر الإدارة والحضور معًا.
- لعبة الرياضيات موجودة؛ بقية الألعاب مقترحات، وترتيبها الحالي مؤقت وباسم اللاعب.
- SQLite والمرفقات وعداد التسبيح موزعة بين عدة أماكن؛ نسخ ملف DB وحده ليس نسخة احتياطية كاملة.

## تصميم سجل الرسائل

الحفاظ على استجابة Array لتوافق الواجهة الحالية. كل رسالة تحمل sequence من SQLite rowid؛ before عدد صحيح موجب، والصفحة مرتبة تنازليًا في SQL ثم تُعكس للعرض. هذا يثبت ترتيب الإدخال حتى لو تساوت created_at. المؤشر ليس وسيلة إثبات هوية، ولا يُغني عن مرحلة الصلاحيات. لا يُستخدم بعد إعادة إنشاء قاعدة البيانات أو VACUUM قد يعيد ترتيب rowid؛ الواجهة تعيد التحميل من آخر صفحة عند بدء جلسة جديدة.

العميل يحتفظ بأقدم sequence وبوجود صفحة أخرى. عند التمرير للأعلى يحمّل الأقدم ويمنع تزامن طلبين ويحافظ على موضع التمرير ويستبعد المكرر بالـid. رقم طلب يتغير عند تبديل المحادثة ويمنع وصول استجابة قديمة إلى المحادثة الجديدة. صفحة كاملة قد تحتاج طلبًا أخيرًا فارغًا لتحديد نهاية السجل.

## قرارات الألعاب

سباق الكتابة: نص واحد للجولة، بدء موحد، تحقق النص والوقت على السيرفر، حساب الدقة قبل السرعة. خمّن الكلمة: بنك كلمات وتلميحات، محاولات محدودة ومهلة، إجابة لا تُرسل للعميل قبل نهاية الجولة. النقاط لا تأتي من العميل. لا وعد بعشر ألعاب قبل اختبار الألعاب الثلاث بصورة مستقلة.

## الاختبارات والتسليم

استخدام scripts/qa-server.cjs ببيانات مؤقتة وبلا beacon، وعدم تعديل بيانات الفصل. npm test لا يغني عن اختبار مرئي على شاشة مدرسية وهاتف، وتجربة شبكة المدرسة. npm run build مطلوب بعد تغييرات HTML/JS المؤثرة في Tailwind. لا نشر أو push ضمن هذه الدفعة دون توثيق النتيجة والتفريق بين الاختبارات المنفذة والمقترحة.

## تحديث تنفيذ الجلسات

بدأت مرحلة 2: auth_sessions يحفظ SHA-256 لرمز عشوائي بصلاحية 12 ساعة؛ cookie HttpOnly وSameSite=Strict، وSecure عند HTTPS. جميع APIs عدا الدخول ومعلومات الشبكة والصلاة والعداد واستقبال Agent القديم تتطلب الجلسة، وSocket.IO يتحقق عند الاتصال وكل حدث. logout يحذف الجلسة ويفصل اتصالاتها. مصدر الدور هو السيرفر، وقراءة/إرسال الخاص والجروبات ترتبط بهوية الجلسة وعضوية الجروب. أُلغي اعتماد x-forwarded-for غير الموثوق لتحديد IP.

الانتقال: أول دخول بعد هذا التحديث ينشئ هوية متصفح محمية بـcookie جهاز عشوائي بدل deviceId المرسل من JavaScript؛ المستخدمون والرسائل القديمة لا تُحذف، لكن ربطها بالهوية الجديدة يحتاج مسار ترحيل إداري قبل نشر التحديث على فصل قائم. فقد cookie الجهاز يعني هوية جديدة، فلا تُعتبر هذه منظومة استعادة حساب مكتملة. صورة شاشة الدخول تُحفظ مؤقتًا في المتصفح وتُرفع بعد نجاح المصادقة.

حدود هذه الدفعة: لم تُؤمَّن روابط /uploads على مستوى صلاحيات كل مرفق، واستقبال /api/netsupport/frame القديم لا يزال مستثنى لحين تنفيذ اقتران Agent. كلمة المرور المشتركة والاعتماد الإداري على MAC لا يزالان قائمين. جلسات HTTP على LAN ليست مشفرة أثناء النقل؛ HTTPS وتغيير آلية حساب الأدمن عمل لاحق. لا يجوز وصف هذه الدفعة بأنها تأمين كامل أو نشرها على الإنترنت باعتبارها جاهزة لذلك.

اختبارات مضافة: رفض HTTP/Socket بلا جلسة؛ منع تغيير المستخدم وrole؛ منع قراءة/إرسال جروب لغير عضو؛ انتهاء الصلاحية وإبطال logout؛ استمرار الرسائل واللعبة والصفحات التاريخية مع المصادقة. الاختبارات تستخدم بيانات معزولة؛ لا تشمل اختبارًا مرئيًا أو تدقيق اختراق شاملًا.
